## P1 封面

各位老师好，我汇报的项目是《皮肤癌图像检测系统》。

本项目基于深度学习技术，实现皮肤镜图像的良恶性自动筛查，并在此基础上提供病变类型参考，最终交付一个可运行的 Web 应用系统。

---

## P2 项目背景与意义

皮肤癌是全球发病率增长最快的恶性肿瘤之一。其中黑色素瘤恶性程度最高，但若在早期发现，五年生存率可达百分之九十九以上。

然而现实困境是：皮肤科医生资源严重不足，基层医疗机构缺乏专业诊断能力，而皮肤镜图像的判读高度依赖医生经验。

我们也调研了现有的同类服务，发现存在一个明显的空白：市面上的网站大多停留在**泛分类的科普介绍**，或者走**医生付费在线问诊**的模式，用户很难找到"直接上传一张皮肤照片、立刻拿到良恶性判断"的自助工具。

这正是本项目的切入点。我们的系统有三个突出特点：**完全免费**，不需要注册付费，游客模式就能检测；**针对性强**，专注皮肤病变的良恶性判别，不做泛泛的分类科普；**操作简单**，拖拽一张照片，秒级出结果和就医建议。

需要强调的是，本系统定位是**筛查工具**，不替代医生诊断。

## P3 需求分析

功能需求来自任务书，核心六个模块：图像上传、图像预处理、深度识别、结果展示、历史记录、用户管理。

在此基础上，我们又扩展了三块：**智能问答**——接入本地医疗知识库大模型，支持文字提问和带图提问，还能解读检测结果；**模型可解释性**——用 Grad-CAM 热力图展示模型关注了图像的哪个区域；**管理后台**——包含看板、用户、记录、审计日志、模型管理等九个页面。

所以现在整个系统的功能模块是八个：图像上传、图像预处理、深度识别、结果展示、智能问答、历史记录、用户管理、后台管理。

非功能需求方面，我们重点关注三点：

第一，**准确率**，任务书要求不低于百分之九十；
第二，**医疗场景的特殊性**——漏诊的代价远大于误报，所以我们把恶性召回率作为核心指标；
第三，**响应速度**，要求单张推理在一秒以内。

## P4 系统架构

系统采用前后端分离架构，整体分为四层。

**表现层**是前端 Web 客户端，基于 React 加 Vite 构建，使用 TailwindCSS 做样式，共六个前台页面，另外还有一个包含九个页面的管理后台，PC 和移动端都做了响应式适配。

**接口层**是 FastAPI 后端服务，共提供四十个 REST 接口，覆盖认证、检测、记录、问答、后台五大模块，并自带交互式 API 文档。

**推理层**采用双模型仲裁：图像良恶性主判定走 PyTorch GPU 集成，病变类型参考走 ONNX INT8 量化模型，医疗问答走本地部署的大语言模型。

**存储层**使用 SQLite 存储用户、检测记录、问答会话和审计日志，图片和模型权重存在本地文件系统。

生产模式下前端构建产物由 FastAPI 托管，单进程单端口就能提供完整服务；对外则通过 Cloudflare Tunnel 做加密公网访问。

## P5 技术栈选型

技术选型遵循三个原则：**低学习成本、快速MVP、低成本**。

深度学习框架选 PyTorch，因为它生态成熟、调试方便；模型选 ResNet 系列，因为它在 ImageNet 上有充分验证，迁移效果好。

后端选 FastAPI，因为它自带 OpenAPI 文档，开发效率高。

前端选 React 加 Tailwind，因为组件化开发适合多功能页面。

数据库选 SQLite，因为本项目数据量小、单机部署，无需引入重量级数据库。

## P6 算法流程

整体流程分为四个阶段。

第一阶段是**数据准备**：从 HAM10000 数据集加载一万零一十五张皮肤镜图像，做七类到二类的映射，按病灶级划分训练测试集。

第二阶段是**模型训练**：使用 ImageNet 预训练的 ResNet50，替换分类头，采用差分学习率加 warmup 策略训练。

第三阶段是**模型优化**：包括阈值调优、模型集成、ONNX 量化三条路径。

第四阶段是**部署上线**：导出 ONNX 模型，接入 FastAPI 服务提供推理接口。

## P7 公网部署上线

这一页专门汇报我们完成的**公网部署**成果。

系统原本只能在本地访问，别人要看得在同一台电脑上操作。这次我们通过 Cloudflare Tunnel 把它发布到了公网，现在任何人打开 **skin.osanu.dpdns.org** 这个网址，不需要安装任何软件，就能直接使用完整的检测功能。

整个链路的原理是：用户访问域名后，请求先到 Cloudflare 的全球边缘节点做 DNS 解析和 HTTPS 加密，然后通过一条加密隧道回到我们本机的服务，隧道由 cloudflared 主动向外建立连接，**因此不需要公网 IP，也不需要做路由器端口映射**。

部署有几个亮点：第一，**免安装免公网 IP**，老师和同学扫码或输网址就能用；第二，**一条隧道挂了两个项目**——皮肤癌检测跑在八千端口、另一个"医小喵"问答项目跑在八千零一端口，复用了同一条隧道；第三，**HTTPS 加密**，浏览器显示的是安全锁标志，医疗数据不会明文传输；第四，**幂等自愈**，服务重启后隧道会自动重连；第五，**零成本**，用的都是免费额度。

## P8 数据工程

数据方面我们做了五项关键工作。

**第一，双数据源**。主力数据集是 HAM10000，一万零一十五张图像、七千四百七十个病灶，这是皮肤镜领域最常用的基准。为了提升泛化能力，我们又从 ISIC 官方渠道引入了 **BCN20000** 数据集——一万二千四百一十三张图像，来自巴塞罗那医院，专门包含指甲、黏膜部位和低色素病变这类**难样本**，正好补我们的短板。两个数据集合并后构成**两万二千四百二十八张**的混训数据集。

**第二，病灶级划分**。这是本项目最重要的专业细节——同一个病灶可能有多张照片，如果随机划分，同一病灶的图片会同时出现在训练集和测试集，导致数据泄漏、指标虚高。我们按病灶 ID 划分，最终验证病灶级交集和图片级交集**都是零**。

**第三，类别映射**。HAM10000 原始是七类标注，我们把黑色素瘤、基底细胞癌、光化性角化归为恶性，其余四类归为良性。

**第四，数据扩容**。主力模型的训练数据从最初的七百九十二张扩充到九千八百零二张，这是后续性能提升的关键。

**第五，跨域测试集**。我们从 BCN20000 里单独切出二千五百三十九张，作为**从不参与训练**的跨域测试集，用来检验模型到底是学到了通用的病变特征，还是只记住了 HAM10000 的域特征。

## P9 模型训练实验

我们总共做了**十一轮**对比实验，这里挑三组关键的说。

**早期探索（第 1 到 6 组）**：从七百九十二张的基线开始，做过增强策略、学习率、数据扩容、类别平衡等尝试。最大的结论是——**数据量是最大瓶颈**：数据从七百九十二张扩到九千八百零二张，AUC 直接从零点八五五提升到零点九一六，涨了六点一个百分点。

**CutMix 数据混合（第 8 组）**：我们发现模型有严重的过拟合，训练集百分之九十七、测试集只有百分之七十九，裂口近十八个百分点。引入 CutMix 之后，把两张图拼接、标签按面积比例混合，迫使模型学习局部纹理而不是背整张图。训练五十轮后，准确率提升到百分之八十五点九二，**过拟合裂口从负十七点九六收窄到负九点零一**，是本次最大的方法论收获。

**模型集成（第 9 到 11 组）**：通过多架构组合搜索，最终确定 ResNet101 加 ConvNeXt-CutMix 的等权集成，准确率**百分之八十六点三八**，AUC **零点九二七六**，这是历史最优。

右边这两张折线图，就是准确率和 AUC 在整个优化过程中的演进曲线。

第一组基线，七百九十二张数据，准确率百分之八十一点六九。

第二组方案A，加强数据增强，结果持平。

第三组 v2 全量，把数据从七百九十二张扩到九千八百零二张，准确率提升到百分之八十四点九八，AUC 提升六点一个百分点——**数据量是二分类最大的瓶颈**。

第四组实验C，强制把数据平衡成一比一，反而降到百分之八十点七五，证明**保持数据量比保持分布平衡更重要**。

第五组方案D，引入 warmup 和标签平滑，曲线更健康但上限没突破。

第六组方案E，换 ResNet101 加二百八十八分辨率，准确率持平但 AUC 提升到零点九一八七。

后续通过 CutMix 数据混合加长训练，单模型准确率提升到百分之八十五点九二，train/test 裂口从负十七点九六收窄到负九点零一。
最后是**多模型加权集成**，准确率**百分之八十六点三八**，AUC 达到**零点九二七六**，筛查模式恶性召回率**百分之九十九点一五**——这是当前的最优方案。

## P10 训练问题诊断

训练过程中我们发现了三个典型问题。

**问题一：最佳成绩出现在第一轮**。这通常是学习率过大的信号——模型一步迈太大，破坏了 ImageNet 预训练特征。我们通过降低骨干学习率并加入 warmup 来缓解。

**问题二：训练正常但测试集掉点**。这是过拟合的表现，通过加强数据增强、提高 Dropout、加入权重衰减来处理。

**问题三：单模型 AUC 卡在零点九一八附近**。多个有效实验的 AUC 高度一致，说明单模型的区分能力已接近数据信息量的天花板。这直接引出了下一页的集成方案。

---

## P11 模型集成

针对单模型 AUC 天花板，我们尝试了模型集成。

**集成方案**：把 ResNet101 和 ConvNeXt-Tiny（CutMix 训练）两个不同架构的模型，softmax 概率逐元素等权平均。

**效果**：相比最优单模型（百分之八十五点九二），集成后的准确率达到**86.38%**，AUC **92.76%**，精确模式恶性召回率**91.53%**。

但这里有个**关键发现**，也是本页最重要的一点：

集成之后概率分布会变，如果仍沿用旧的阈值，准确率甚至可能**低于单模型**（早期实验中阈值零点五时集成只有百分之八十四点五一）。

原因在于：多个模型的概率平均之后，输出分布变得更集中，原阈值不再是最优分割点。我们在**验证集**上重新扫描六十一个操作点完成标定；当前成员组合（ResNet101 加 ConvNeXt-CutMix）最终标定为**零点四八**——注意标定用验证集、报告用测试集，避免用测试集调参。

**这个发现的意义**：集成提升了模型的排序能力，但判定阈值必须重新校准才能兑现为准确率。任何改变输出分布的改动——集成、蒸馏、重训练、数据混合——都需要重新确定决策阈值。

另外我们尝试了 TTA 测试时增强，结果准确率反而下降。原因分析是：皮肤镜图像具有方向性，垂直翻转和旋转会破坏解剖学方位感。这个失败我们也如实记录在文档中。

## P12 七类病变类型分类

在良恶性主结论之外，我们增加了七类病变类型分类，作为**辅助参考信息**。

**功能定位**必须明确：主结论（良性/恶性，准确率百分之八十六点三八）是核心判断；类型判断（七类，准确率百分之七十四点三二）**仅作参考**，界面明确标注不可作为诊断依据。功能能力与呈现方式必须匹配，不能把参考信息包装成诊断结论。

**实现亮点**：我们没有下载任何外部数据。因为 HAM10000 原始数据本来就有七类标注，只是二分类时被合并了。所以复用原始标注加硬链接，**零额外磁盘消耗**，三十分钟完成训练。

**效果**：准确率百分之七十四点三二，宏平均 AUC 零点九二五八。表现较好的类别包括黑色素细胞痣、血管性病变和基底细胞癌。

**主要问题**：黑色素细胞痣与良性角化、黑色素瘤互相混淆——因为这三者在医学上本就难以区分，专业医生也需结合病理。另外皮肤纤维瘤训练样本只有一百一十三张，精确率偏低。

**核心洞察**：AUC 高达零点九二五八但准确率只有百分之七十四点三二，说明模型**具备排序能力，但类别边界难划**——瓶颈是少数类的样本量，而非模型能力。

## P13 模型优化（一）：阈值调优

医疗场景的核心诉求是**不漏诊**，而非追求最高准确率。

所以我们做了阈值调优，提供三档工作模式：

**筛查模式**，阈值零点二零，恶性召回率**百分之九十九点一五**——二百一十三张测试集里只漏诊一张，漏诊率**百分之零点八五**。适合初步筛查。

**平衡模式**，阈值零点三三，恶性召回百分之九十五点七六；**精确模式**是默认档，阈值零点四八，准确率**百分之八十六点三八**。

**精确模式**适合已有明确怀疑、需要减少误报的场景。

**实测证据**：有一个临界样本，恶性概率百分之四十四点四五。在零点三二阈值下判定为恶性，正确识别；在零点五阈值下判定为良性，导致漏诊。

这说明阈值确实能改变判定结果。筛查模式用约七点五个百分点的准确率代价，把漏诊从十张降到**一张**——在「宁可误报不可漏诊」的初筛场景里，这个交换是划算的。

---

## P14 模型优化（二）：量化压缩

任务书要求降低模型体积和计算量。我们用 ONNX Runtime 做 INT8 静态量化。

**结果**：两个模型都实现了**三点九三倍**的体积压缩，从九十兆降到二十二点九兆，精度损失控制在百分之一以内。

**加载速度**：主模型加载从四点七秒降到零点二二秒，加速二十倍；七类模型加载从一点三六秒降到零点二一秒，加速六点五倍。

**技术路线的曲折**：我们最初尝试 PyTorch 原生量化，但发现当前环境缺少 fbgemm 量化算子，卷积层无法量化。于是改用工业界更标准的 ONNX Runtime 路径，最终成功。

**这个排查过程本身也是技术能力的体现**——遇到工具链限制时，能够定位原因并换用成熟方案。

## P17 技术难点与应对

项目过程中遇到四个关键技术难点。

**难点一：数据泄漏风险**。同一病灶多张图可能跨集。解决方案是病灶级划分，最终验证病灶交集为零。

**难点二：跨文件系统 IO 瓶颈**。训练时发现 GPU 利用率掉到零，排查发现是从 Windows 挂载盘读图太慢。测速显示本地盘比挂载盘快八倍。解决方案是把数据复制到本地盘训练。

**难点三：PyTorch 量化算子缺失**。静态量化报错，定位到是当前环境未编译 fbgemm 量化卷积算子。解决方案是改用 ONNX Runtime 路径。

**难点四：集成后准确率反而下降**。通过分析发现是阈值失配，重新扫描阈值后解决。

这四个难点的共同点是：**先定位根因，再选择方案**，而不是盲目尝试。

## P18 不足与改进方向

我们诚实呈现当前系统的不足。

**第一，准确率百分之八十六点三八，未达任务书百分之九十的目标**。原因包括：测试集仅二百一十三张，每错一张准确率变化零点四七个百分点，统计波动较大；HAM10000 二分类的公开基准多在百分之八十五到九十二之间。

**第二，七类类型准确率仅百分之七十四点三二**。主要瓶颈是少数类样本不足，皮肤纤维瘤仅一百一十五张训练图。我们已用 Grad-CAM 热力图作为可解释性补充。

**第三，推理依赖 GPU 才能达到六十五毫秒**，无 GPU 时会回退到 CPU，约一到两秒每张。已部署 ONNX INT8 量化模型作为兜底，二十二点九兆，CPU 可跑。

**第四，公网部署这一项已经完成**——这是本次新增的内容。我们通过 Cloudflare Tunnel 打通了 HTTPS 公网访问，现在任何人都能在线使用。

对应改进方向：用已经构建好的**两万二千四百二十八张混训数据集**重训，提升二分类准确率；扩充七类少数样本；细化七类解释流程；完善功能界面与多端适配；探索产品市场化。

## 附：答辩预案

### Q0：你们说做了跨数据集验证，结果怎么样？

我们做了，并且**如实呈现了一个不太好看但很有价值的结论**。

把在 HAM10000 上训练的集成模型，直接拿到 BCN20000 的二千五百三十九张跨域测试集上评测，结果准确率是**百分之七十四点五一**，AUC **零点八二一四**；而同一个模型在 HAM10000 自己的测试集上是百分之八十六点三八、AUC 零点九二七六。

**泛化落差是负十点九四个百分点**，说明模型存在比较明显的**域依赖**——它学到的既有通用的病变特征，也有一部分是 HAM10000 这个数据域的专有特征。

这个结论回答了本项目一个关键问题，也正好是**引入混训数据最有力的动机**：我们已经在 BCN20000 的样本上构建好了两万二千四百二十八张的混训数据集，下一步就是用它重训，观察跨域指标能提升多少。这是我们后续要做的最有价值的实验。

同时要说明，AUC 的落差比准确率小（零点九二七六降到零点八二一四），说明模型的**排序区分能力**跨域后保留了一部分，主要损失来自阈值漂移和良性侧误报增加。

### Q1：为什么准确率没到百分之九十？

**答**：准确率百分之八十六点三八未达百分之九十的目标。但需要说明三点：

第一，测试集仅二百一十三张，每错一张准确率变化零点四七个百分点，统计波动较大。

第二，HAM10000 二分类的公开 baseline 多在百分之八十五到九十二之间，我们的水平属于合理区间。

第三，更重要的是，医疗筛查的核心诉求是「不漏诊」而非最高准确率。我们的系统在筛查模式下恶性召回率百分之九十九点一五，漏诊率仅百分之零点八五，同时 AUC 达到零点九二七六，表明模型具备优秀的区分能力。

### Q2：集成相比最优单模型只提升了零点四六个百分点，值得做吗？

**答**：从准确率看提升有限，但从两个角度看价值显著：

第一，AUC 从单模型的零点九一八七提升到**零点九二七六**，这是模型区分能力的实质增强，不受阈值影响。

第二，筛查模式的漏诊从**十张降到一张**（漏诊率 8.47% → 0.85%），临床意义明显。

第三，这个实验过程中我们发现了一个重要的工程问题——集成后必须重新校准阈值。这个洞察本身就有技术价值。

### Q3：七类分类准确率只有百分之七十四，会不会误导用户？

**答**：我们在产品设计上做了三重防护：

第一，**明确定位**：界面将类型判断标注为"参考信息"，视觉层级明显弱于主结论。

第二，**显式声明**：类型参考区域直接展示「准确性约百分之七十四，低于良恶性判断，不可作为诊断依据」。

第三，**方向校验**：七类的概率可以聚合为良性/恶性两组，与主结论交叉验证。若方向矛盾，会提示"结果存在不确定性"。

功能能力与呈现方式必须匹配，这是医疗 AI 产品的基本设计原则。

### Q4：为什么不用外部数据提升七类准确率？

**答**：我们评估过 ISIC Archive 和 Kaggle ISIC 2019 数据集。不采用的原因是投入产出比：

下载九点三吉字节数据、临时占用十八吉字节磁盘、耗时两到三小时，预期提升到百分之七十八到八十二。而七类本身定位是"辅助参考"，百分之七十四点三二已经够用。

更重要的是，外部数据存在设备、光照、人群的风格差异，可能引入新的不确定性。我们选择先用同源数据把功能做扎实。

如果后续需要提升，接口已经预留，路径也已经验证可行。

### Q5：这个系统的实际应用价值是什么？

**答**：本系统的定位是**初筛工具**，不是诊断系统。

实际价值体现在三个场景：

第一，**个人自查**：普通人发现皮肤异常时，可以快速判断是否需要就医，避免延误也可以减少不必要的焦虑。

第二，**基层辅助**：基层医疗机构缺乏皮肤科医生，本系统可以提供初步筛查建议。

第三，**教学演示**：作为 AI 医疗应用的完整案例，覆盖数据、模型、工程、部署全流程。

所有输出都带有明确的免责声明：本系统仅供健康参考，不能替代专业医疗诊断，如有异常请及时就医。
