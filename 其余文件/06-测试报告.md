### 5.3 混淆矩阵

```
                  预测良性    预测恶性
```

| 单元格 | 数量 | 含义 | 临床影响 |

**关键说明**：通过**筛查模式（阈值0.20）**可将漏诊降到最低（实测 213 张仅漏诊 1 张，恶性召回 99.15%），代价是误报增多（44 张）。

### 5.5 关于准确率未达 90% 的分析

**现状**：ONNX 量化模型准确率 84.51%、当前生产集成模型 86.38%，均未达成任务书"≥90%"的目标。**原因分析**：

| 因素 | 说明 |
|------|------|
| **测试集规模小** | 仅 213 张，**每错 1 张 = 准确率变化 0.47%**，统计波动大 |
| **数据难度高** | HAM10000 的黑色素瘤与色素痣在视觉上高度相似，皮肤科医生也易误判 |
| **数据量限制** | 全量 10015 张训练（含 7330 病灶），仍小于 ImageNet 级别 |
| **公开基线水平** | HAM10000 二分类的公开 baseline 多在 85-92% 之间 |
| **AUC 已达 0.91** | 模型整体区分能力优秀，accuracy 受阈值影响 |

**多维度呈现（更能反映真实能力）**：

| 指标 | 数值 | 评价 |
|------|------|------|
| AUC | **0.9059**（ONNX INT8）/ **0.9276**（集成，当前生产）| 优秀，接近 0.93 的优秀线 |
| 恶性召回（筛查模式）| **95.76%** | 漏诊率仅 4.24%，临床价值高 |
| Macro F1 | 86.08% | 类别均衡性良好 |

**改进方向**（已在报告中列出）：
1. 阈值调优（已实现，筛查模式召回 95.76%）
2. 提高分辨率（已实验 288×288，AUC 提升至 0.9187）
3. 模型集成（多模型投票）
4. 扩大数据集（引入 ISIC 其他年份数据）
5. 更强骨干（ResNet101/EfficientNet）

## 六、并发性能测试

| 并发数 | 请求数 | 成功 | 耗时 | QPS | 平均延迟 |
|--------|--------|------|------|-----|---------|
| 1 线程 | 5 | 5 | 0.21 s | 24.0 | 41.7 ms |
| 4 线程 | 20 | 20 | 0.86 s | 23.4 | 42.8 ms |
| 8 线程 | 40 | 40 | 1.85 s | 21.6 | 46.3 ms |

**分析**：

| 观察 | 结论 |
|------|------|
| QPS 稳定在 21-24 | ONNX Runtime 内部线程池限流，避免过载 |
| 8 线程延迟略升（46ms vs 42ms）| CPU 推理资源竞争，但衰减可控（+10%）|
| **零失败** | 100% 成功率，服务稳定性良好 |
| 吞吐 ≈ 24 QPS | 满足单机部署需求（约 8.6 万次/小时）|

**并发设计要点**：
- Predictor 使用线程锁（`threading.Lock`）串行化推理，防止并发资源冲突
- ONNX Session 设置 `intra_op_num_threads=4`，控制 CPU 占用
- SQLite 使用 WAL 模式，读写并发不阻塞

### 9.6 缺陷记录（管理后台迭代）

| # | 问题 | 严重程度 | 原因分析 | 修复 |
|---|------|---------|---------|------|
| 1 | 老库报 `no such column: role` | 高 | `CREATE TABLE IF NOT EXISTS` 对已存在的表**不会修改结构**，改建表语句无效 | `init_db()` 内加幂等 `_migrate()`：`PRAGMA table_info` 查列 + `ALTER TABLE ADD COLUMN` |
| 2 | 迁移把测试残留账号提为管理员 | 中 | "首个注册账号=管理员"策略遇到测试残留账号（无人知晓密码）→ 后台失联 | 新建专用管理员 `admin`，将残留账号降回 user |
| 3 | `admin_api.py` 导入报 `beyond top-level package` | 中 | 该文件与 `config.py` 同在 `app/` 包内，用 `from ..` 越界 | 改用单点 `from . import config` |
| 4 | `/admin/*` 全部 404 | 中 | 静态目录 `isdir` 在**启动时**判定，先起服务后建目录 → 未挂载 | 重启 uvicorn |
| 5 | 误以为管理路由全部丢失 | 低（排查）| FastAPI 0.141 的 `include_router` 生成 `_IncludedRouter` 延迟展开对象，`app.routes` 看不到 | 改用 `app.openapi()["paths"]` 探测（实际 24 个接口齐全） |
| 6 | 测试脚本注册用户报 422 | 低（测试脚本）| `EmailStr` 拒绝保留域名（`.local` / `.test` / `.invalid`）| 测试数据改用正常域名 |
| 7 | 浏览器实测输出 0 字节 | 低（测试脚本）| Chrome 是 Windows 程序，`--user-data-dir` 传 WSL 路径会静默退出 | 改用 Windows 路径 |
| 8 | 断言"检测有结论"失败 | 低（测试脚本）| `POST /api/predict` 结论嵌套在 `result` 子对象，顶层无 `label` | 改为 `r["result"]["label"]` |
| 9 | 未登录守卫用例假失败 | 低（测试脚本）| 上轮验证把 token 留在 Chrome profile，下轮直接是登录态 | 脚本运行前清空 profile（幂等修复）|
| 10 | 后端自测脚本重跑失败 | 低（测试脚本）| 固定测试用户密码被上轮重置，重跑用旧密码登录必失败 | 改用时间戳唯一用户名（幂等修复）|

> 第 6–10 项为**测试脚本自身缺陷**（非产品代码问题），修复后脚本可重复执行，作为回归资产保留。

## 十、缺陷记录

### 10.1 测试过程中发现并修复的问题

| # | 问题 | 严重程度 | 原因分析 | 修复 |
|---|------|---------|---------|------|
| 1 | ONNX INT8 模型加载后 `/api/predict` 报 401 | 中 | `Depends(get_optional_user)` 依赖中 `Header` 参数未显式指定 `alias="Authorization"`，FastAPI 无法解析 | 重命名为 `resolve_optional_user` 并加 `alias` |
| 2 | 后端加载到训练中实验的中间产物（acc 74.65%）| 中 | 模型候选路径优先级未考虑"训练中"目录会持续覆盖 best.pt | 调整优先级，训练中的实验排最后 |
| 3 | 训练过程 GPU 利用率掉到 0% | 高 | 从 `/mnt/d`（Windows 挂载盘）读图，跨文件系统 IO 慢，dataloader 供不上数据 | 数据复制到 WSL 本地盘，读速提升 8 倍 |
| 4 | PyTorch 静态量化报算子缺失 | 中 | torch 2.11 cu128 构建未包含 fbgemm 量化卷积算子 | 改用 ONNX Runtime 量化路径 |
| 5 | 测试脚本 4xx 请求判定失败 | 低（测试脚本）| `requests` 的 4xx Response 对象为 falsy，`bool(r and ...)` 恒为 False | 改用 `r is not None and ...` |
| 6 | 测试脚本 `R["model"].append()` 报错 | 低（测试脚本）| `R["model"]` 初始化为 dict 而非 list | `rec()` 中按类别区分处理 |

### 9.2 遗留问题

| # | 问题 | 影响 | 计划 |
|---|------|------|------|
| 1 | 准确率未达 90% 目标（86.38%，集成模型）| 中 | 已通过数据混合、模型集成、阈值标定优化到 86.38%，并在文档中说明数据上限与实际水平 |
| 2 | ONNX INT8 单张推理比 FP32 略慢（26 vs 21ms）| 低 | 小 batch 场景的正常现象；大批量或边缘部署时 INT8 优势显现 |

   管理后台具备**角色权限体系**（401 未登录 / 403 非管理员 / 防自降级 / 防锁死）

   支撑真实运营场景
