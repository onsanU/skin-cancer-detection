## 一、项目背景与意义

### 1.1 项目背景

根据世界卫生组织癌症统计，皮肤癌是最常见的癌症之一，也是死亡率较高的癌症类型。黑色素瘤是其中恶性程度最高的一种，且容易发生转移，危及患者生命。**早期诊断和筛查是提高黑色素瘤治愈率的关键。**

传统皮肤癌诊断依赖经验丰富的皮肤病专家通过皮肤镜图像判断，但有经验专家的缺乏限制了大规模早期诊断的开展。近年来，深度学习技术在医学图像分析领域取得突破性进展，基于深度残差网络的算法在皮肤癌识别方面已达到与专业医生相当的准确率。

随着 Web 技术的发展，基于浏览器的 Web 应用具有跨平台、无需安装、易于传播等优势，用户可通过电脑或手机浏览器直接访问，为皮肤癌早期诊断和筛查提供便捷途径。

### 1.2 项目意义

| 维度 | 价值 |
|------|------|
| **业务价值** | 普及皮肤癌早期诊断意识，帮助用户及时发现皮肤异常，降低发病率与死亡率 |
| **技术价值** | 实践深度学习在 Web 环境的部署与应用，探索前后端分离架构在医疗 AI 领域的最佳实践 |
| **社会价值** | 缓解医疗资源分布不均问题，为偏远地区用户提供便捷的皮肤健康自检工具 |

## 二、需求分析

### 2.1 功能性需求

| 编号 | 模块 | 需求描述 | 优先级 |
|------|------|---------|--------|
| FR-01 | 图像上传 | 支持拖拽或点击选择上传皮肤病变图像，支持 jpg/png/bmp/webp，提供实时预览 | 高 |
| FR-02 | 图像预处理 | 对上传图像进行归一化、尺寸调整（224×224）、格式转换 | 高 |
| FR-03 | 深度学习识别 | 构建皮肤癌分类模型，实现良性/恶性二分类，准确率目标 ≥90% | 高 |
| FR-04 | 结果展示 | 可视化展示识别结果（良性/恶性）、置信度分数，提供健康建议与就医指导 | 高 |
| FR-05 | 历史记录 | 保存用户检测历史，支持查看过往结果、图像对比、记录导出 | 中 |
| FR-06 | 用户管理 | 用户注册、登录、个人信息管理，保障数据安全 | 中 |
| FR-07 | 阈值调节 | 提供多档判定阈值（筛查/平衡/精确模式），适配不同使用场景 | 中 |

### 2.2 非功能性需求

| 类别 | 要求 |
|------|------|
| **性能** | 单张图像推理延迟 < 500ms；API 响应时间 < 1s |
| **兼容性** | 支持 Chrome / Firefox / Safari / Edge 最新两个版本；响应式适配 PC 与移动端 |
| **安全性** | 密码加盐哈希存储；JWT 认证；上传文件类型与大小校验；路径穿越防护 |
| **可用性** | 服务启动自动加载模型；模型加载失败时优雅降级并报告状态 |
| **可维护性** | 配置集中管理；前后端分离；模块化路由 |
| **合规性** | 显著位置展示医疗免责声明；用户数据本地存储不外传 |

### 2.3 约束条件

- 开发语言：Python 3.12+（后端/算法）、JavaScript（前端）
- 硬件约束：训练环境为 RTX 5070 Laptop 8GB 显存
- 数据约束：HAM10000 数据集，测试集固定 213 张（恶性118/良性95）
- 免责约束：本系统仅为健康自检辅助工具，不能替代专业医生诊断

### 3.3 算法流程

```
数据准备阶段
├── HAM10000 数据集（10015 张皮肤镜图像）
├── 7 类 → 2 类映射（mel/bcc/akiec=恶性，nv/bkl/df/vasc=良性）
├── 病灶级划分（同一 lesion_id 的图片不跨训练/测试集，防数据泄漏）
└── 固定测试集 213 张（恶性118/良性95），训练集随实验调整

模型训练阶段
├── ResNet50 迁移学习（ImageNet 预训练权重）
├── 数据增强（随机裁剪/翻转/旋转/色彩抖动/随机擦除）
├── 差分学习率（backbone 慢、分类头快）
├── Warmup + 余弦退火 + 早停
└── AMP 混合精度 + 梯度裁剪

模型优化阶段
├── 阈值调优（扫描 0.20~0.80，产出三档工作模式）
├── L1 非结构化剪枝（30% 稀疏度）
└── ONNX INT8 静态量化（QDQ，4x 体积压缩）

推理部署阶段
├── Predictor 单例自动探测加载可用模型
├── ONNX 优先（体积小、加载快）/ PyTorch 回退
└── FastAPI 提供 RESTful 推理接口
```

## 四、系统模块设计

| 模块 | 职责 | 关键设计 |
|------|------|---------|
| **用户认证模块** | 注册、登录、JWT 签发校验 | PBKDF2-SHA256 加盐哈希（12万次迭代）；手写 JWT 避免额外依赖 |
| **图像上传模块** | 接收上传、格式校验、磁盘存储 | 扩展名 + MIME 双校验；10MB 限制；UUID 防重名 |
| **图像预处理模块** | 尺寸调整、归一化 | Resize 224×224（与训练一致）；ImageNet 均值方差标准化 |
| **推理服务模块** | 模型加载与预测 | 单例模式；线程锁防并发；checkpoint 自描述（arch/img_size 自动恢复） |
| **结果展示模块** | 良恶性判定、置信度、健康建议 | 分场景建议库；医疗免责声明强制展示 |
| **历史记录模块** | 记录 CRUD、筛选、分页、导出 | 按用户隔离；CSV 导出带 BOM 防中文乱码 |
| **阈值配置模块** | 三档工作模式 | 筛查 0.20 / 平衡 0.33 / 精确 0.48（验证集标定）|
| **角色权限模块** ★ | 用户角色（user / admin）、管理员守卫 | 首个注册账号自动为管理员；管理接口未登录 401 / 非管理员 403；防自降级 |
| **管理后台模块** ★ | 全站数据看板、记录管理、用户统计、账号管理、系统状态 | 独立 `admin_api.py`（11 接口）；AdminLTE 纯静态前端；与主检测系统解耦 |

> ★ 标记为 **v1.1.0 新增**（管理后台迭代，2026-09-14）

## 五、关键设计决策

### 5.1 为什么按"病灶级"而非"图片级"划分数据集？

HAM10000 中同一病灶可能有多张不同角度/时间的照片。若按图片随机划分，同一病灶的图片可能一张进训练集、一张进测试集，导致模型"考前见过题"，准确率虚高但实际无用。

**本系统严格按 `lesion_id` 划分**：同一病灶的所有图片必完整落在训练集或测试集的同一侧。训练/测试集病灶交集为 0。

### 5.2 为什么提供三档阈值而非固定 0.5？

医疗场景中"漏诊（恶性判为良性）"的代价远大于"误诊（良性判为恶性）"。经阈值扫描实验：

| 模式 | 阈值 | 恶性召回 | 漏诊率 | 适用场景 |
|------|------|---------|--------|---------|
| 筛查模式 | 0.20 | 99.15% | 0.85% | 初步筛查，宁可误报不可漏诊（漏诊 1 张）|
| 平衡模式 | 0.33 | 95.76% | 4.24% | 准确率与召回兼顾 |
| 精确模式 | 0.48 | 91.53% | 8.47% | 默认，准确率优先（漏诊 10 张）|

### 5.3 为什么采用 ONNX 而非 PyTorch 原生量化？

PyTorch 原生量化工具链在本机环境受限：动态量化对 Conv2d 无效（主要优化 Linear），静态量化缺少 fbgemm 量化算子（`NotImplementedError: quantized::conv2d.new`）。

因此采用工业界标准路径：PyTorch → ONNX → onnxruntime INT8 静态量化，实现 **3.93x 体积压缩 + 21倍加载加速**，精度损失仅 0.47%。

## 六、部署架构

```
┌─────────────────────────────────────────────┐
│           开发/演示环境（WSL2）               │
│  ├─ 后端: 127.0.0.1:8000 (uvicorn)          │
```

- **开发模式**：前端 Vite 开发服务器 + 代理转发，支持热更新
- **生产模式**：`npm run build` 产出静态文件，由 FastAPI 挂载 `/app` 路径统一提供服务
- **管理后台**（v1.1.0）：AdminLTE 纯静态资源由 FastAPI 挂载 `/admin` 路径，**无需构建步骤**，
  与前台 `/app` 并列共存，单端口（8000）即可访问全站三个入口：

| 入口 | 路径 | 技术形态 |
|------|------|---------|
| 前台检测系统 | `/app/` | React 18 + Vite 构建产物 |
| 管理后台 | `/admin/` | AdminLTE 纯静态（零构建） |
| API 文档 | `/docs` | FastAPI 自动生成 |

## 八、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 数据集类别不平衡（良性:恶性 ≈ 4:1） | 模型偏向多数类 | 类别权重 + 病灶级分层抽样 |
| 训练数据量小（792张） | 过拟合 | 数据扩容至 9802 张，强增强 |
| 测试集小（213张） | 指标波动大 | 同时报告 AUC / 召回 / F1 等多维指标 |
| 模型误判风险 | 医疗风险 | 显著免责声明 + 分档阈值 + 建议就医 |
| 跨文件系统 IO 慢 | 训练中断 | 数据复制到本地盘（提速 8 倍） |
| 隐私数据泄露 | 合规风险 | 本地存储、密码哈希、路径防护 |
| 管理后台越权访问 | 数据泄露 | 双层守卫（后端 401/403 + 前端 guardAdmin）；记录按用户隔离；密码哈希不可逆 |
| 管理员误操作锁死后台 | 运维中断 | 防自降级 / 防自禁用 / 系统须保留至少一名管理员（均返回 400） |
