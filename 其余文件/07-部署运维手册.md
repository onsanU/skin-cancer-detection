## 一、部署架构总览

```
                    ┌──────────────────────────────┐
   Windows 浏览器 ──▶│  WSL2 (Ubuntu)               │
                    │  ┌────────────────────────┐  │
                    │  │  开发模式（推荐演示）    │  │
                    │  │  Vite Dev :5173         │  │
                    │  │      │ /api 代理         │  │
                    │  │      ▼                  │  │
                    │  │  FastAPI :8000          │  │
                    │  └────────────────────────┘  │
                    │  ┌────────────────────────┐  │
                    │  │  生产模式               │  │
                    │  │  FastAPI :8000          │  │
                    │  │   ├─ /api/*   接口       │  │
                    │  │   ├─ /app     前端静态   │  │
                    │  │   └─ /admin   管理后台   │  │ ← v1.1.0
                    │  └────────────────────────┘  │
                    └──────────────────────────────┘
                                 │
                    ┌────────────▼─────────────┐
                    │  ONNX Runtime (CPU)      │
                    │  model_int8.onnx 22.9MB  │
                    └──────────────────────────┘
```

**特点**：生产模式下前端构建产物由 FastAPI 直接托管，**单进程单端口**即可提供完整服务，简化部署。

### 1.1 三个访问入口（同一端口 8000）

| 入口 | 路径 | 部署方式 | 说明 |
|------|------|---------|------|
| 前台检测系统 | `/app/` | React 构建产物（需 `npm run build`）| 面向普通用户 |
| **管理后台** ★ | `/admin/` | AdminLTE 纯静态（**零构建，直接托管**）| 面向管理员，v1.1.0 新增 |
| API 文档 | `/docs` | FastAPI 自动生成 | 含全站 24 个接口 |

**管理后台部署特性**（与前台的关键差异）：

- **无需构建步骤**：静态资源随代码放在 `backend/static/admin/`，FastAPI 一次性挂载
- **零外网依赖**：AdminLTE / Bootstrap / 图标字体全部本地化（2.0MB），断网可用
- **独立性**：管理后台的增删改**不影响**前台构建产物，反之亦然

## 三、首次部署

### 3.1 步骤概览

```
① 准备 Python 虚拟环境
② 安装 Python 依赖
③ 确认模型文件存在
④ 构建前端（生产模式）
⑤ 启动后端服务
⑥ 验证服务
```

### 3.2 详细步骤

#### 步骤 ① 准备虚拟环境

```bash
# 已有实训环境可直接复用
cd ~
python3 -m venv venv               # 若不存在则创建
source venv/bin/activate
```

> 说明：`start.sh` 会自动探测 `venv/`、`.venv/`、`~/shixun-venv` 等常见位置；也可用 `SKIN_VENV_PY=/path/to/python` 显式指定解释器。

#### 步骤 ② 安装依赖

```bash
# 后端依赖
pip install fastapi uvicorn[standard] \
    pydantic email-validator python-multipart \
    onnx onnxruntime pillow numpy requests

# 前端依赖
cd frontend
npm install
```

#### 步骤 ③ 确认模型文件

```bash
cd 皮肤癌图像系统

# 检查 ONNX 量化模型（生产推荐，22.9MB）
ls -lh models_compressed/model_int8.onnx

# 检查 PyTorch 模型（回退用，90MB）
ls -lh models_vE_r101_288/best.pt
ls -lh models_vE_r101_288/best.pt
```

**若模型文件缺失**，需要先训练或从备份恢复（见第七章）。

#### 步骤 ④ 构建前端（生产模式）

```bash
cd frontend
npm run build
# 产出：frontend/dist/（index.html + assets/）
```

构建成功后，后端启动时会**自动检测并挂载** `frontend/dist` 到 `/app` 路径。

#### 步骤 ⑤ 启动后端服务

```bash
cd backend

# 开发模式（自动重载）
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# 生产模式（多 worker，无重载）
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

**启动日志示例**：

```
======================================================================
皮肤癌图像检测系统 - 后端服务启动中...
======================================================================
[DB] 初始化完成: .../backend/skin_cancer.db
[Predictor] ✅ ONNX 后端已加载: .../models_compressed/model_int8.onnx
[Predictor]    体积 22.91MB (较 PyTorch 压缩约 4x) 耗时0.22s
[Predictor] 预热完成
[启动] 模型就绪=True 设备=cuda
[启动] 上传目录=.../backend/uploads
[启动] 已挂载前端静态文件: /app -> .../frontend/dist
======================================================================
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000
```

> **注意**：`--workers 1` 是有意为之。多 worker 会导致**每个进程都加载一份模型**，内存成倍增长。
> 单 worker + ONNX 多线程已能满足本项目吞吐（24 QPS）。

#### 步骤 ⑥ 验证服务

```bash
# 健康检查
curl http://127.0.0.1:8000/api/health

# 前端页面（生产模式）
curl -I http://127.0.0.1:8000/app/

# API 文档
# 浏览器打开 http://127.0.0.1:8000/docs
```

## 四、管理后台部署与运维（v1.1.0）★

管理后台**无需额外部署步骤** —— 静态资源随后端代码一起提供，启动后端即自动挂载。

### 4.1 部署检查

后端启动日志应包含以下两行，否则说明静态目录未被识别：

```
[启动] 已挂载管理后台: /admin -> .../backend/static/admin
[启动] 已挂载前端静态文件: /app -> .../frontend/dist
```

⚠️ **挂载判定发生在服务启动时**：若在服务运行期间才创建 `static/admin/` 目录，
`/admin/*` 会全部 404，**必须重启后端**才能挂载。

### 4.2 验证部署

```bash
# 1) 后台首页可达（应 200 且返回 HTML）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/admin/

# 2) 静态资源可达
curl -s -o /dev/null -w "%{http_code}\n" \
  http://127.0.0.1:8000/admin/vendor/adminlte/css/adminlte.min.css

# 3) 管理接口需管理员身份（未带 token 应 401）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/admin/api/stats
# 期望输出：401
```

### 4.3 管理员账号

| 项目 | 值 |
|------|-----|
| 用户名 | `admin` |
| 密码 | `<密码>` |
| 邮箱 | `admin@skin.local` |
| 角色 | `admin` |

> ⚠️ **公网部署前必须修改默认密码**。密码以 PBKDF2-SHA256 哈希存储，**不可逆查看**，
> 忘记只能由其他管理员在「账号管理」页重置。
> 重置方式：管理后台 → 账号管理 → 找到账号 → 点钥匙图标 → 输入新密码。

**新建管理员**（命令行方式，无可用管理员时使用）：

```bash
cd backend
python -c "
import sys; sys.path.insert(0,'.')
from app import database
from app.services.auth import hash_password
import secrets
alphabet = 'abcdefghjkmnpqrstuvwxyzABCDEFGHJKMNPQRSTUVWXYZ23456789'
pwd = 'Skin@' + ''.join(secrets.choice(alphabet) for _ in range(10))
if database.get_user_by_username('admin'):
    u = database.get_user_by_username('admin')
    database.set_user_role(u['id'], 'admin')
    database.set_user_password(u['id'], hash_password(pwd))
else:
    database.create_user_ext('admin', 'admin@skin.local',
                             hash_password(pwd), '系统管理员', 'admin')
print('管理员密码:', pwd)
"
```

### 4.4 数据库迁移（升级已有部署时）

`users` 表新增 `role` 字段，由 `init_db()` 内的 `_migrate()` **幂等自动执行**，无需手动干预：

```bash
# 手动触发迁移（正常启动服务时也会自动执行）
cd backend && python -c "
import sys; sys.path.insert(0,'.')
from app import database; database.init_db()"
```

启动日志会打印迁移结果：

```
[DB] 迁移: users.role 已添加                      # 首次升级时出现
[DB] 迁移: 首个账号 'xxx' 已提升为管理员            # 库中无管理员时出现
[DB] 初始化完成: .../skin_cancer.db
```

⚠️ **迁移坑提醒**：若老库中最早注册的账号是**测试残留账号**（无人知晓密码），
"首个账号提为管理员"会把管理员给到该账号 → 后台无法登录。
此时用 §4.3 的命令行方式**新建专用管理员**，并将残留账号降级：

```bash
python -c "
import sys; sys.path.insert(0,'.')
from app import database
database.set_user_role(<残留账号id>, 'user')   # 降回普通用户
"
```

### 4.5 管理后台日常运维

| 场景 | 操作 |
|------|------|
| 查看全站数据 | 管理后台 → 数据看板（30 秒自动刷新） |
| 排查某用户问题 | 用户统计 → 点用户行看详情 → 或按用户名筛选记录 |
| 清理异常记录 | 检测记录 → 筛选 → 删除（同时删磁盘图片） |
| 禁用刷量账号 | 账号管理 → 点禁用图标（禁用后该用户无法登录） |
| 修改自己密码 | 账号管理 → 找到自己 → 钥匙图标 → 重置（**降级/禁用自己会被拒绝**）|
| 清空某用户记录 | 账号管理 → 橡皮擦图标（需二次确认） |

**安全机制**（均返回 400 拒绝）：
- 管理员**不能降级自己** → 避免后台失联
- 管理员**不能禁用自己**
- 系统**始终保留至少一名可用管理员**

### 4.6 管理后台故障排查

| 现象 | 原因 | 解决 |
|------|------|------|
| `/admin/` 返回 404 | 静态目录未被挂载（启动时目录不存在）| **重启后端** |
| 页面能打开但样式全无 | vendor 资源缺失或路径错误 | `curl` 检查 `/admin/vendor/adminlte/css/adminlte.min.css` 是否 200 |
| 登录后立刻被踢回登录页 | token 失效或 `role` 非 admin | 检查 `/api/auth/me` 返回的 `role`；确认账号已提为 admin |
| 管理接口全部 401 | token 未带上（localStorage 被清）| 重新登录 |
| 管理接口全部 403 | 登录账号 `role != admin` | 用管理员账号登录，或提权该账号 |
| 数据看板数字不更新 | 后端重启后 CSRF/token 失效 | 刷新页面重新登录 |
| 修改 config.py 后无变化 | uvicorn 无 `--reload` 不热载 | **重启后端** |

## 五、日常运维

### 5.1 启动服务

**方式一：手动启动（前台，便于观察日志）**

```bash
cd backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

**方式二：后台启动（推荐日常使用）**

```bash
cd backend
nohup python -m uvicorn app.main:app \
    --host 0.0.0.0 --port 8000 > /tmp/skin_backend.log 2>&1 &
echo $! > /tmp/skin_backend.pid
```

**方式三：一键脚本（推荐）**

创建 `start.sh`：

```bash
#!/bin/bash
# 皮肤癌检测系统一键启动
set -e
PROJ="皮肤癌图像系统"
PY=python

echo "== 检查服务是否已在运行 =="
if curl -s --max-time 2 http://127.0.0.1:8000/api/health > /dev/null 2>&1; then
    echo "服务已在运行: http://127.0.0.1:8000"
    exit 0
fi

echo "== 启动后端 =="
cd "$PROJ/backend"
nohup $PY -m uvicorn app.main:app --host 0.0.0.0 --port 8000 \
    > /tmp/skin_backend.log 2>&1 &
echo $! > /tmp/skin_backend.pid

echo "== 等待就绪 =="
for i in $(seq 1 30); do
    if curl -s --max-time 2 http://127.0.0.1:8000/api/health > /dev/null 2>&1; then
        echo "✅ 后端就绪: http://127.0.0.1:8000"
        break
    fi
    sleep 1
done

echo ""
echo "访问地址:"
echo "  前端页面  http://127.0.0.1:8000/app/"
echo "  API 文档  http://127.0.0.1:8000/docs"
echo "  健康检查  http://127.0.0.1:8000/api/health"
```

### 5.2 停止服务

```bash
# 方式一：用 PID 文件
kill $(cat /tmp/skin_backend.pid) 2>/dev/null && echo "已停止"

# 方式二：按进程名
pkill -f "uvicorn app.main:app" && echo "已停止"

# 方式三：确认端口释放
ss -tlnp | grep 8000 || echo "端口 8000 已释放"
```

### 5.3 重启服务

```bash
pkill -f "uvicorn app.main:app"; sleep 2
cd backend
nohup python -m uvicorn app.main:app \
    --host 0.0.0.0 --port 8000 > /tmp/skin_backend.log 2>&1 &
sleep 20 && curl -s http://127.0.0.1:8000/api/health | head -c 200
```

### 5.4 查看日志

## 六、配置管理

### 6.1 配置文件位置

`backend/app/config.py` —— **所有可调参数集中在此**。

### 6.2 关键配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `USE_ONNX` | `True` | 是否优先用 ONNX 推理（体积小、加载快）|
| `ONNX_MODEL_PATH` | `models_compressed/model_int8.onnx` | ONNX 模型路径 |
| `ENABLE_ENSEMBLE` | `True` | 是否启用多模型集成（主判定）|
| `ENSEMBLE_THRESHOLD` | `0.48` | 集成模式默认阈值 |
| `MALIGNANT_THRESHOLD` | `0.48` | 单模型模式默认阈值 |
| `ENABLE_TYPE_PREDICT` | `True` | 是否启用七类类型参考 |
| `DEVICE` | `"cuda"` | PyTorch 推理设备（ONNX 走 CPU）|
| `MAX_UPLOAD_MB` | `10` | 上传文件大小上限 |
| `SECRET_KEY` | 开发默认值 | **生产环境必须通过环境变量覆盖** |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `10080`（7天）| JWT 有效期 |

### 6.3 常见配置修改

**切换推理后端为 PyTorch**（精度略高，内存占用更大）：

```python
# config.py
USE_ONNX = False
```

**修改默认判定阈值**：

```python
# config.py
ENSEMBLE_THRESHOLD = 0.48
```

**生产环境设置密钥**（重要）：

```bash
export SKIN_SECRET_KEY="your-random-secret-key-here"
# 或在启动前写入 .env 并 source
```

> ⚠️ **安全提示**：`SECRET_KEY` 用于签发 JWT。若使用默认值，攻击者可伪造 token。
> 生产部署时**必须**通过环境变量覆盖为随机长字符串。

### 6.4 阈值预设调整

`config.py` 中的 `THRESHOLD_PRESETS` 定义了前端可选的三种工作模式：

```python
THRESHOLD_PRESETS = {
    "screening": {"name": "筛查模式", "value": 0.20, "desc": "..."},
    "balanced":  {"name": "平衡模式", "value": 0.33, "desc": "..."},
    "accurate":  {"name": "精确模式", "value": 0.48, "desc": "..."},
}
```

修改后需**重启服务**生效。

```bash
cd 皮肤癌图像系统
```

```bash

# 恢复数据库
```

## 九、故障排查

### 9.1 服务无法启动

| 现象 | 可能原因 | 排查与解决 |
|------|---------|-----------|
| `Address already in use` | 端口被占用 | `ss -tlnp \| grep 8000` 找占用进程，`kill` 掉或换端口 |
| `ModuleNotFoundError: fastapi` | 依赖未装 | `pip install fastapi uvicorn` |
| `ModuleNotFoundError: onnxruntime` | ONNX 未装 | `pip install onnx onnxruntime`，或 `config.USE_ONNX=False` 回退 |
| 启动卡在加载模型 | 模型文件过大/损坏 | 检查日志中 `[Predictor]` 输出，确认 `model_path` 正确 |

### 9.2 模型未就绪

**现象**：`/api/health` 返回 `model.ready: false`，`/api/predict` 返回 503。

**排查步骤**：

```bash
# 1. 查看健康检查中的错误信息
curl -s http://127.0.0.1:8000/api/health | python3 -c "
import json,sys
d = json.load(sys.stdin)
print('ready:', d['model']['ready'])
print('error:', d['model']['load_error'])
print('path :', d['model']['model_path'])
"

# 2. 确认模型文件存在
ls -lh models_compressed/model_int8.onnx
ls -lh models_vE_r101_288/best.pt

# 3. 手动验证模型可加载
python -c "
import onnxruntime as ort
s = ort.InferenceSession('models_compressed/model_int8.onnx')
print('ONNX 加载成功，输入:', s.get_inputs()[0].shape)
"
```

**常见原因**：
- 模型文件被删除或路径变更
- 训练中的实验目录 `best.pt` 被覆盖为未完成状态
- 磁盘满导致保存失败

### 9.3 推理失败

| 现象 | 原因 | 解决 |
|------|------|------|
| 400 不支持的图片格式 | 上传非图片文件 | 前端已限制，用户侧提示 |
| 400 图片过大 | 超过 10MB | 修改 `MAX_UPLOAD_MB` 或压缩图片 |
| 500 推理失败 | 图像损坏 / 模型异常 | 查看日志堆栈，用正常图片重试 |
| 503 模型未就绪 | 模型加载失败 | 见 8.2 |

### 9.4 前端无法访问

| 现象 | 原因 | 解决 |
|------|------|------|
| `/app/` 返回 404 | 未构建前端 | `cd frontend && npm run build` |
| 页面空白 | 构建产物损坏 | 删除 `dist/` 重新构建 |
| API 请求 404 | 代理配置问题 | 开发模式检查 `vite.config.js` 的 proxy；生产模式确认路径为 `/api/*` |
| 跨域错误 | CORS 未生效 | 检查 `main.py` 中 CORSMiddleware 配置 |

### 9.5 性能问题

| 现象 | 排查 | 优化 |
|------|------|------|
| 推理变慢 | `curl /api/health` 看 `avg_infer_ms` | 关闭其他占 CPU 进程；增大 `ONNX_THREADS` |
| 并发下 QPS 上不去 | 观察 CPU 使用率 | 单机 CPU 推理的固有上限；如需更高可部署多实例 |
| 内存占用高 | `ps aux \| grep uvicorn` | 确认 `--workers 1`；ONNX 比 PyTorch 省内存 |

### 9.6 数据库问题

| 现象 | 原因 | 解决 |
|------|------|------|
| `database is locked` | 并发写入冲突 | WAL 模式已启用；检查是否有长事务 |
| 数据丢失 | 未备份 | 从 `~/skin_backup/` 恢复 |
| 数据库损坏 | 异常断电 | `PRAGMA integrity_check` 检查；必要时从备份恢复 |

## 附录：常见问题（FAQ）

**Q1：为什么用 ONNX 而不是直接用 PyTorch 模型？**
A：ONNX INT8 模型仅 22.9MB（PyTorch 90MB），加载快 21 倍（0.22s vs 4.71s），
内存占用低，且**无需 GPU 即可部署**。精度损失仅 0.47%。

**Q2：为什么 `--workers 1`？**
A：每个 uvicorn worker 是独立进程，会各自加载一份模型。多 worker 会导致内存成倍增长。
单 worker + ONNX 多线程（`ONNX_THREADS=4`）已能提供 24 QPS，满足本项目需求。

**Q3：服务重启后数据会丢吗？**
A：不会。用户与记录存储在 `backend/skin_cancer.db`，上传图片在 `backend/uploads/`，
均为磁盘持久化。

**Q4：能让局域网其他设备访问吗？**
A：可以。`--host 0.0.0.0` 已监听所有网卡。其他设备访问 `http://<本机IP>:8000/app/`。
若需公网访问，建议配合 Cloudflare Tunnel 或 Nginx 反向代理 + HTTPS。

**Q5：训练脚本怎么跑？**
A：见 `交付文件/09-项目说明文档.md` 中的训练章节，
核心命令：`python src/train_resnet50.py --data ~/skin_cancer_data/processed_v2_full`
