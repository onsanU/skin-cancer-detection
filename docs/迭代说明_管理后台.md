# 迭代说明 · 管理后台（AdminLTE）

> **迭代版本**：v1.1.0 ｜ **完成日期**：2026-09-14
> **迭代主题**：参照「医小喵」项目的后端架构，为皮肤癌检测系统补齐管理后台
> **定位**：与主检测系统（ResNet50 良恶性二分类）解耦的**运营管理端**，用于查看全站数据、管理检测记录与账号

---

## 一、迭代目标

皮肤癌检测系统原本只有「前台检测侧」能力（注册登录 / 上传检测 / 检测历史 / 个人统计 / CSV 导出），
缺少**运营管理侧**能力：没人能看全站数据、没法定量管理所有用户的检测记录、没有账号权限体系。

本次迭代对标「医小喵（医疗健康智能问答助手）」已验证的后端管理架构，为皮肤癌检测系统补齐：

| # | 目标 | 说明 |
|---|------|------|
| 1 | **账号角色体系** | users 表引入 `role`（user / admin），支持管理员权限分级 |
| 2 | **管理后台 API** | 独立管理模块，11 个接口覆盖看板 / 记录 / 用户 / 账号 / 系统 |
| 3 | **管理后台界面** | AdminLTE v4 纯静态后台，6 个页面，零外网依赖 |
| 4 | **访问安全** | 所有管理接口强制管理员守卫；未登录 401 / 非管理员 403；前端页面守卫 |
| 5 | **零影响升级** | 现有接口/前端**零改动**（幂等迁移，不动任何已有数据） |

## 二、技术方案

### 2.1 为什么选 AdminLTE 纯静态模板而不是 React 后台

| 方案 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| **AdminLTE 纯静态**（选用） | 零构建链、直接由 FastAPI 托管、与医小喵同构、1 天可交付 | 不是工程化项目 | ✅ **采用** |
| React + AntD 独立工程 | 技术栈统一 | 多一套构建链、工作量大 | ❌ |
| React 内嵌现有工程 | 一次构建全站 | 前台是检测工具向，后台是数据表格向，风格冲突 | ❌ |

**关键理由**：后台是「运营工具」，页面数量有限、交互形态固定（表格+表单+弹窗），
用纯静态模板可以**零构建成本**交付；而主检测系统保持 React 工程不动，两者解耦更清晰。

### 2.4 账号体系设计

- **role 字段**：`user`（默认）/ `admin`
- **首个注册账号**自动成为管理员（与医小喵一致；本次为已存在数据的库做兼容，见 §四.1）
- **访问规则**：
  - `/admin/api/*` 全部依赖 `get_current_admin` → 未登录 **401**，非管理员 **403**
  - `/admin/*.html` 每页首行 `guardAdmin()` → 无 token / 非 admin 自动跳登录页
- **安全守卫**：
  - 管理员不能**降级自己**（否则后台失联）→ 400
  - 管理员不能**禁用自己** → 400
  - 系统始终保留**至少一名可用管理员** → 400
- **密码**：沿用项目原有 PBKDF2-SHA256（12 万次迭代 + 随机盐），**哈希不可逆查看**，管理端只能「重置」

## 四、关键技术决策与踩坑记录

### 1. 已存在数据库的兼容迁移（本次最关键的工程决策）

`skin_cancer.db` 已有 **33 个用户 / 1408 条记录**，直接改建表语句对已存在的库**无效**（`CREATE TABLE IF NOT EXISTS` 不会改结构）。

**方案**：`init_db()` 里加幂等迁移 `_migrate()`：
```python
cols = {r["name"] for r in conn.execute("PRAGMA table_info(users)")}
if "role" not in cols:
    conn.execute("ALTER TABLE users ADD COLUMN role TEXT NOT NULL DEFAULT 'user'")
# 无管理员时，把最早注册的账号提升为管理员（保证后台可用）
```
- **每次启动幂等执行**，不缺列则跳过
- **不动任何已有数据**（新列默认 `user`）
- 用**独立管理员账号**而非占用测试残留账号（见下）

### 2. 管理员账号的选择

迁移逻辑会把「最早注册的账号」提为管理员，但本项目最早的账号 `testcat` 是**测试残留**（无人知道密码）。
处理方式：
- `testcat` 降回 `user`
- **新建专用管理员账号 `admin`**（与前台用户账号分离，符合安全习惯）

### 3. `EmailStr` 拒绝保留域名

测试脚本用 `xxx@test.local` 注册被 **422** 拒绝：
```
The part after the @-sign is a special-use or reserved name that cannot be used with email.
```
→ `.local` / `.test` / `.invalid` 等保留域名不能被 `EmailStr` 接受，测试数据要用正常域名（`.com`）。

### 4. FastAPI 0.141 的 `_IncludedRouter` 与路由探测

新版 FastAPI 的 `include_router()` 不再把路由平铺进 `app.routes`，而是生成 `_IncludedRouter` 延迟展开对象。
**症状**：`for r in app.routes: r.path` 只能看到 7 条（误以为路由全丢）。
**正确探测**：`app.openapi()["paths"]` 才能看到全部 24 个接口。

### 5. `admin_api.py` 的相对导入层级

`admin_api.py` 与 `config.py` 同在 `app/` 包下，导入必须用**单点** `from . import config`，
写成 `from .. import config` 会报 `attempted relative import beyond top-level package`。

### 6. 静态目录挂载必须在根挂载之前

新增的 `app.mount("/admin", ...)` 必须放在原有 `/app` 挂载**之前**（更严格说：在所有 `mount` 之前），
否则路由优先级会打架。另外**目录存在性在启动时判定** —— 本次先起了服务、后建目录，导致 `/admin/*` 全部 404，
**重启后端才挂上**。

### 7. AdminLTE 资源的本地化清单（大陆网络必须离线）

`npm pack` 下载后抽取（`--registry=https://registry.npmmirror.com`）：
- `admin-lte@4` → `dist/css/adminlte.min.css`（**已内置 Bootstrap CSS**）+ `dist/js/adminlte.min.js`
- **`bootstrap@5.3`** → `dist/js/bootstrap.bundle.min.js`（**AdminLTE 的 JS 不含 Bootstrap**，Modal/Dropdown 必需）
- `bootstrap-icons` → `bootstrap-icons.min.css` + `fonts/*.woff2`
- `overlayscrollbars` → CSS + `browser/overlayscrollbars.browser.es6.min.js`

合计 2.0 MB，**零外网 CDN 依赖**（大陆网络下 CDN 会白屏）。

### 8. headless Chrome 验证的两个坑

- **`--user-data-dir` 不能传 WSL 路径**：Chrome 是 Windows 程序，传 `/home/...` 会静默退出（输出 0 字节）。
  必须用 Windows 路径（`C:\Users\...\Temp\...`）。
- **登录态页面不能直接 dump-dom**：未登录会被守卫重定向，dump 出来是登录页。
  正确做法：先访问一个同源的注入页把 token 写进 `localStorage`，再用**同一 user-data-dir** 访问目标页
  （验证完删除注入页）。

### 9. 页面守卫的验证姿势

「未登录访问 `index.html` 渲染出登录页」**不是 bug，而是正确行为**。
断言要写 `'id="loginForm"' in html`（说明被拦走了），而不是「页面有内容」。

### 10. 检测接口响应是嵌套的

`POST /api/predict` 的结论在 **`result`** 子对象里（`result.label` / `result.label_cn` / `result.probability`），
顶层只有 `record_id` / `advice` / `image_url` / `saved` / `type_reference` / `disclaimer`。
断言写 `r["label"]` 会拿到 `None`。

### 6.4 本次迭代未做的事（边界说明）

- **不做知识库/模型管理**：管理端只管运营数据，不触碰模型与数据集链路（避免影响主功能）
- **不做批量操作**：记录删除是逐条（批量删除会带来误删风险，需要二次确认设计）
- **不做操作审计日志**：管理员操作未记录审计表（后续可加）
- **测试残留账号未清理**：库里仍有 30+ 个 `test_*` / `perf_*` / `demo_*` 测试账号（本次仅降级了 `testcat`），

## 七、下一步建议

| 优先级 | 事项 | 理由 |
|--------|------|------|
| 高 | 修改默认管理员密码 | 公网部署前必做 |
| 高 | 清理测试残留账号与记录 | 演示环境整洁，也让统计数据更真实 |
| 中 | 一键启动脚本 `start.sh` + 根 README | 服务目前需手动起，重启电脑即失效 |
| 中 | 管理员操作审计日志 | 后台已能改角色/密码，留痕更规范 |
| 低 | 记录批量删除 / 批量导出 | 数据量大时提升效率 |
| 低 | 后端 `sync_token_to_admin` 单点登录打通 | 前台登录后台免二次登录 |
