# CutMix / MixUp 数据混合实验记录

> 日期：2026-09-17
> 目的：突破二分类准确率天花板（历史最优 85.45%）
> 结论：**CutMix 有效治愈过拟合，配合长训 + 集成后准确率提升至 86.38%（历史新高）**
> 产物目录：`models_mix_cutmix/` `models_mix_mixup/` `models_mix_cutmix_long/`

## 一、实验背景

前一阶段 10 轮实验（见 `docs/训练实验记录.md`）显示：准确率卡在 85.45%，
AUC 稳定在 0.89~0.91，判断为数据规模瓶颈。

本次实验针对一个**此前未处理的病症**：**过拟合**。

历史 ConvNeXt+Focal 的典型曲线：

| 轮次 | train acc | test acc | 裂口 |
|---|---|---|---|
| 6 | 85.84% | **85.89%** | +0.05%（峰值）|
| 10 | 93.41% | 84.66% | -8.75% |
| 16 | 97.41% | 79.45% | **-17.96%** |

train 从 85.8% 冲到 97.4%，test 反而掉了 6.4 个点 —— 模型开始"背答案"。
**CutMix/MixUp 正是针对这一病症的标准手段**（在图像上做区域裁剪替换/线性叠加，
构造混合标签，迫使模型学更鲁棒的特征）。

## 二、代码实现（`src/train_sota.py`）

新增三个纯函数 + 三个命令行参数，**默认关闭，完全向后兼容**：

```python
rand_bbox(h, w, lam)                      # 按 lam 比例裁矩形
mix_batch(x, y, mode, alpha, prob)        # 返回 (x_mix, y_a, y_b, lam, applied)
mixed_loss(criterion, out, y_a, y_b, lam) # lam*CE(y_a) + (1-lam)*CE(y_b)
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--mix` | none | none / cutmix / mixup / both |
| `--mix-alpha` | 1.0 | Beta(α,α)，1.0 为 CutMix 论文推荐值 |
| `--mix-prob` | 0.5 | 每个 batch 触发的概率 |
| `--select-metric` | medical | medical=0.5×召回+0.5×macro_f1 / acc=纯准确率 |

### ⚠️ 关键实现细节：训练指标防污染

CutMix 后 batch 内标签已被混合，**若仍用 y 统计训练 acc 会得到错误数字**。
正确处理：只统计「未被覆盖」的样本（`y_a == y_b`）：

```python
if mixed:
    keep = (y_a == y_b)          # 同类交换看不出差异，只有这些样本标签可信
else:
    keep = torch.ones_like(y_a, dtype=torch.bool)
y_true.extend(y_a[keep].tolist())
y_pred.extend(out.argmax(1)[keep].tolist())
```

**副作用（需知悉）**：mask 后的样本集不等同于原训练分布，
因此 **CutMix 下的 train acc 会显著低于 test acc（本项目约 63~76% vs 83~86%），
这是正常现象，不代表模型没学好** —— 判断收敛要看 test 曲线，不能看 train acc。

### 极端 lam 处理

`Beta(1,1)` 是均匀分布，抽到 lam<0.05 或 >0.95（几乎就是原图）的概率约 10%。
初始实现是"跳过"，实测触发率只有 ~90%；改为**重抽**后触发率 100%
（`prob=0.5` 时实测 52.8%，符合预期）。

## 四、对照实验（三组，同种子 42 / 288px / Focal Loss / strong 增强）

| 实验 | 轮数 | 混合 | 选模 | test acc | 恶性召回 | AUC | 耗时 |
|---|---|---|---|---|---|---|---|
| 历史基线 | — | 无 | medical | 85.89% | 90.05% | 0.9269 | — |
| A组 | 20 | cutmix | medical | 79.34%（best）<br>83.10%（ep19 峰值）| 97.46%（best）| 0.9075 | 19 min |
| B组 | 18 | mixup | medical | 82.63%（best）| 96.61% | 0.9173 | ~18 min |
| **C组（长训）** | **50** | **cutmix** | **acc** | **85.92%** | **91.53%** | **0.9207** | **49 min** |

> ⚠️ A组 的 best.pt 只有 79.34%，但它训练的**第 19 轮实际达到 83.10%**。
> 因为选模公式 `0.5×召回+0.5×macro_f1` 选中了召回高的轮次（97.46%），
> 牺牲了准确率 —— **差 3.76%**。这正是 C组 改用 `--select-metric acc` 的原因。

### 关键观察

**1. 过拟合被彻底治好**（这是本次最大的方法论收获）

```
历史基线:  train 97.41% / test 79.45%   裂口 -17.96%   ❌ 崩
C组:       train 75.83% / test 84.84%   裂口  -9.01%   ✅ 稳
```

C组 50 轮训练，train acc 始终未超过 80%，test 稳定在 84~86% 震荡 ——
**没有任何过拟合迹象**。

**2. 20 轮不够，收益被截断**

A组 ep19 时 test acc 仍在上升（79.3→81.2→83.1），曲线未达峰，被 20 轮上限截断。
延长到 50 轮后达峰 **85.92%**（第 35 轮），比 A组高 2.82%。

**3. 选模规则会显著影响结果**

A组按 `0.5×召回+0.5×macro_f1` 选模，选中的 best.pt 准确率仅 79.34%，
但同一次训练的 ep19 实际达到 83.10% —— **选模规则偏了 3.76%**。
改用 `--select-metric acc` 后，C组选中 85.92% 的最优轮次。

> 教训：**混合训练会系统性抬高召回率**，若选模公式含召回项，
> 会偏向"召回高但准确率一般"的轮次。冲准确率时应改用纯 acc 选模。

### 7.2 HTTP 端到端（真实上传）

| 阈值 | label | 恶性概率 | 判定阈值 | 耗时 |
|---|---|---|---|---|
| 0.20 | malignant | 0.4996 | 0.20 | 69.9 ms |
| 0.33 | malignant | 0.4996 | 0.33 | 41.1 ms |
| 0.48 | malignant | 0.4996 | 0.48 | 39.8 ms |

三档 `malignant_prob` 完全一致 → 阈值只影响判定、不影响概率 ✔
临时用户与记录已清理，数据库恢复原状 ✔

> 注：测试图 `prob=0.4996` 恰好卡在阈值附近，三档均判恶性 ——
> 这是一个很好的「边界样本演示」案例。

### 7.3 排查过程中发现的两个坑

1. **字段名陷阱**：`predict_bytes` 返回的 `probability` 是**按 label 取的置信度**
   （判良性时返回 p_benign），不是恶性概率。取恶性概率必须用 `malignant_prob`。
   最初测试脚本误用 `probability`，得到 TN=0（全判恶性）的假象。
2. **HTTP 响应是嵌套的**：`/api/predict` 返回 `{record_id, result:{...}, advice, image_url}`，
   概率字段在 `result` 里，不在顶层。

## 十、方法论沉淀

1. **过拟合要看 train/test 裂口**，不要只看 test 曲线 —— 裂口持续扩大就是过拟合
2. **CutMix/MixUp 会系统性抬高召回率**，选模公式含召回项时会选偏
3. **混合训练下 train acc 失去参考价值**（mask 后样本分布变了），看 test
4. **极端 lam 应重抽而非跳过**（β(1,1) 下有 10% 概率浪费混合机会）
5. **小数据集上"轮数不够"常被误判为"方法无效"** —— A组 20 轮 83.10%，
   同样配置 50 轮 85.92%，差 2.82%
6. **换模型必须重标定阈值**，旧阈值不可沿用
7. **验证要打到服务进程内**（用 Predictor 直调），才能排除 HTTP 层的干扰，
   并与离线标定做零误差比对
